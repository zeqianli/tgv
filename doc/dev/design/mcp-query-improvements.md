# Design: remaining MCP query improvements

Status: proposed, not implemented.

## Context

The [variant-support feedback session](../feedback/2026-10-07-mcp-variant-support-session.md) found that agents rebuilt per-base data from CIGAR strings, hit SQL errors only after the data had loaded, and got silently wrong results from lowercase reference bases.

Already addressed:

- SQL shows unsigned integers wider than a byte as `i64`, so subtracting coordinates can go negative.
- `cigar_ops.read_offset`, the packed `cigar_ops.op` column, and the per-base functions `allele_at`, `qual_at`, `offset_at`, and `insertion_after` replace the CIGAR running sums.
- Base qualities are numeric Phred scores (`list[u8]`). `--phred` sets the file encoding, and the default `auto` assumes Phred+33 unless the first loaded reads hold a score above Q93.
- Reference bases are uppercase in every table, and `soft_masked` marks repeat sequence.
- The `coverage` description says that it excludes duplicates and QC failures.

The remaining work follows the same three goals: invalid queries should fail early and deterministically, the interface should be easy to use, and no feature should cost much memory or time for a narrow use.

## Plan

### 1. Check queries before loading data

- **Plan against empty tables first.**
  - `Dataset::query` (`crates/gv-session/src/session.rs`) plans the SQL against the empty catalog frames, the ones `SqlTable::catalog` builds with `finish(vec![])`, with the same function registry. It then runs `collect_schema()`.
  - This catches unknown tables and columns, unsupported functions and window frames, type errors, and bad per-base function arguments before `load_query_region` reads any BAM data.
- **Region tables without `region`.** Use `polars::sql::extract_table_identifiers` to find region tables named without `region`, and fail with `field: "region"`. This replaces matching `"relation"` in the Polars message.
- **`dry_run`.** Add `QueryRequest.dry_run: bool`, default `false`.
  - When it is true, validate and return the output `columns`, the name and dtype of each, without loading data.
  - `region` is optional in that mode and only checked for validity when given.

### 2. Self-correcting errors

Add a small map in `crates/gv-session/src/schema/query.rs` from the Polars error to a hint, appended to the `invalid_input`/`sql` message:

- An unsupported function: "Call describe_tables for the supported functions." For `unicode`, `ascii`, and `ord`, add "Base qualities are numeric: use `qual_at(c.op, pos)`."
- An unsupported window frame: "Use `read_offset` or `offset_at` instead of running sums."
- A regex parse error: "`strpos` and `regexp_like` take a regex; escape metacharacters, or use LIKE."

### 3. A self-sufficient `describe_tables`

- **Built-in functions.** Add a sorted `builtin` list from `polars::sql::keywords::all_functions()` next to the per-base functions. It is generated by Polars, so it cannot drift.
- **Dialect quirks.** Add a `quirks` list:
  - `strpos` and `regexp_like` take a regex.
  - Inequality joins are inner-only.
  - The only supported window frame is `ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`.
  - `substr` and list subscripts count from 1, while `read_offset` and `offset_at` count from 0.

### 4. Absolute paths

Apply `std::path::absolute` to each file and reference path in `classify_and_build_tracks` (`crates/gv-core/src/settings.rs`). `get_dataset.tracks[].source` and `tracks.source` then report absolute paths for headless and viewer sessions alike. Today, relative paths come back as given.

### 5. Read-level columns

Add `read_len`, `clip_start`, and `clip_end` to `reads`:

- `read_len` is the SEQ length, including soft clips and excluding hard clips.
- `clip_start` and `clip_end` are the soft-clip lengths at each end, in alignment orientation.
- They come from the CIGAR in `append_read` (`crates/gv-core/src/alignment/tables.rs`), at a few bytes per read.

`read_len` makes the strand-aware position in a read a single expression: `CASE WHEN r.reverse THEN r.read_len - 1 - offset_at(c.op, pos) ELSE offset_at(c.op, pos) END`.

### 6. Auxiliary tags

`HP` lets agents split evidence by haplotype, and `NM`, `PS`, and `RG` are also commonly asked for. The tags are already in memory, in `Alignment.records`. Options, still undecided:

- **Typed columns on `reads`** (`nm`, `hp`, `ps`, and `rg`), read from the records when the session builds the table. This is simple and costs O(reads) lookups per query, but it fixes the set of tags.
- **A `tag(track_id, read_id, name)` function** that reads any tag lazily, only for rows that survive the filters. This is general, but it requires sharing `Alignment.records` through an `Arc`.

### 7. Read budget for deep data

At high depth, such as 50,000x, a 100 kb query region holds billions of bases, and `load_query_region` can run out of memory without a clear error.

- Count reads while streaming the region into the query state.
- Past a fixed budget, such as 2 million reads, stop and fail with a structured error that gives the region, the reads seen, and a suggested narrower width.
- Optionally, estimate depth from the BAM index chunk sizes to suggest a width before loading. This is approximate, so it should only produce hints, never rejections.

### 8. One copy of each base in core

Each base is stored twice: in the noodles `RecordBuf` and in `cigar_runs.seq` and `qual`. Slicing the record buffers instead of copying them would roughly halve alignment memory, for the TUI as well as for queries.

### 9. Documentation fix

`doc/src/server.md` uses `center.contig` as an example error `field`, which no tool emits. Replace it with `region`.

## Not planned

- **Adding tracks to a live viewer.** This comes with [adding and removing tracks at runtime](./runtime-tracks.md).
- **Per-interval highlight labels.**
- **A `pileup` table or an `allele_support` tool.** Rows grow with depth times width, and the per-base functions answer the same questions on demand.
- **More `coverage` counts,** such as by strand, by indel, or above Q20. These are GROUP BY queries over `cigar_ops` with the per-base functions.
