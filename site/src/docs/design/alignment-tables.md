# Alignment tables in memory

The alignment schemas, table construction, and sparse annotation helpers live together in `alignment/tables.rs`. Each loaded alignment region has Polars tables for reads, the nine noodles CIGAR operation kinds, records without CIGAR operations, and sparse base annotations. The core columns follow the LAMF alignment map layout, except that SEQ payloads use UTF-8 strings for simpler access. `ContigHeader` remains the authority for merged contig names and references; there is no separate reference or header table in memory.

## Read identity and display bounds

The `read_id` column is the zero-based position in the region's original record order. `Alignment` owns exactly one decoded `RecordBuf` for each ID. Filtering, sorting, and pairing keep these IDs stable so the viewer can retrieve original CIGAR operations, tags, and read details without reconstructing a record from the tables.

The reads table adds nullable `UInt64` columns `stacking_start` and `stacking_end`. They describe one-based, inclusive display bounds, including projected soft clips. Both are null for records without an alignment position. Stacking, overlap queries, hit testing, sorting, and pair construction use these columns. There is no stored read geometry vector or separate spans table. Visibility, track positions, and loaded-region state remain application state beside the tables. Genomic positions use tgv’s one-based, inclusive convention throughout the tables, queries, annotations, and renderer. Read IDs, operation indexes, and offsets into SEQ remain zero-based indexes.

Repository readers convert local BAM, remote BAM, and CRAM records into noodles `RecordBuf`s in batches of 1,024 records. Tables are populated with a consuming builder, starting with `AlignmentTables::default().add_records(&batch, &reference, contig_index)?`. Each call builds columns for the new records and appends DataFrame chunks using `vstack_mut`, rather than rebuilding the existing rows. IDs continue from the existing reads table height, including IDs in CIGAR, unmapped, and annotation tables. Empty batches leave the tables unchanged. Batches for one region use the same header, reference, and contig index. Appending succeeds for the complete set of tables before the builder returns.

All table fields are public, so callers use `tables.reads` and `tables.base_modifications` directly. The `run(kind)` method selects a CIGAR table by noodles' operation kind; each CIGAR table has a named public field: `r#match` (`M`), `sequence_match` (`=`), `mismatch` (`X`), `insertion` (`I`), `deletion` (`D`), `reference_skip` (`N`), `soft_clip` (`S`), `hard_clip` (`H`), and `padding` (`P`). The owning alignment and pair table follow the same field-access convention.

Noodles supplies SAM flags and CIGAR kinds. Read-consuming CIGAR tables and the unmapped table store SEQ as Polars `String` (UTF-8), preserving the ASCII sequence from the original `RecordBuf`. Base offsets are therefore byte offsets, and there is no custom four-bit packing or decoding. Missing read names, mapping qualities, SEQ, and quality scores are null. This uses more memory than packed bases but simplifies slicing, comparisons, queries, and eventual Python access. Present quality payloads remain binary. Optional tags remain exclusively in the original `RecordBuf` objects and can be queried through `alignment.records[read_id].data()`. There is no duplicate tags table. Batch construction uses separate append functions for read fields, CIGAR runs, and unmapped payloads, each updating mutable vectors directly. DataFrames are constructed inline in `build_batch`, without wrapper structs or a second row-oriented copy.

The read table stores mutable display state in `show: Boolean` and `y: UInt64`. Filtering replaces visibility, and stacking or base sorting replaces row positions, without removing or reordering stable read-ID rows. The stacker uses a temporary vector to build the y column; no display vectors or y-index cache remain in `Alignment`. Hidden rows receive y zero. Depth uses direct column reductions to check visibility and compute the maximum zero-based y plus one, returning zero when no rows are visible. Hit testing uses lazy row selection.

## Sparse annotations

A CIGAR run is uniquely identified by `(read_id, op_index)` across all nine operation tables. The reference mismatch table stores that key, `run_offset: UInt32`, `ref_pos: UInt64`, and `base: UInt8`. It contains only mismatches discovered by comparing `M` bases with the loaded reference at construction time. Explicit `X` runs already identify mismatches, and `=` runs are trusted. Unavailable reference positions and other contigs are never compared.

The base modification table stores the run key, `run_offset: UInt32`, `display_pos: UInt64`, nullable `code: UInt8` and `chebi_id: UInt32`, `probability: UInt8`, and `source_order: UInt64`. Exactly one modification variant is populated, matching noodles' `Modification`. Coordinates are one-based and include projected soft clips. Inserted bases have no projected reference position, so their original annotations remain available in the original record sidecar. MM/ML parsing supports the legacy tags, preserves absent probabilities as null (the renderer retains its display default of 255), and preserves source order. Invalid MM data produces a diagnostic containing the read ID during loading.

A reference cache refresh constructs replacement mismatch tables directly from each alignment’s match table and contig index before committing the sequence and annotations. Cached reads do not need to be reloaded. Annotation storage is separate because a run can have many optional base annotations, and their coordinates and probabilities should be independently queryable.

## Viewport drawing and paired reads

There are no `RenderingContext` objects or caches. `Alignment::query_viewport` selects a batch of read IDs and filters the CIGAR and annotation tables. Run projections add clipped `display_start`, `display_end`, and `run_offset` columns without changing the stored CIGAR schema or copying decoded sequences. The offset preserves the correct base index when a run crosses the viewport or the left contig boundary. Hard clips and padding consume no display interval. Insertions retain their reference cursor as a point anchor. Strand flags and terminal display bounds determine arrows.

The renderer consumes these query results through immutable alignment references. It reads only visible soft-clip and explicit mismatch bases from the SEQ strings, applies sparse mismatch and modification rows, and preserves CIGAR operation order at compressed zoom levels. Scratch terminal cells exist only for the current viewport and frame.

The paired view owns a Polars pair table with `pair_id`, `read_1_id`, nullable `read_2_id`, and nullable stacking bounds in the same one-based, inclusive convention. Both pair and singleton rows store `show: Boolean` and `y: UInt64`. Visibility and row placement have no parallel vectors or y-index cache. Polars groups primary, nonsupplementary paired reads by non-null `qname`. Each qname produces one group containing its minimum and maximum read IDs; groups with one record have a null second ID. Additional records in a group do not create more pairs. A final sort by the first read ID keeps pair IDs deterministic. Missing names, unpaired records, secondary records, and supplementary records remain in the separate `singles` DataFrame. An eligible read without a loaded mate stays in the pair table with a null second ID. Pairs and singles share one stacking space, and both participate in sorting, rendering, and mouse hit queries. The renderer batches both mates' run queries and resolves gaps, overlaps, and conflicts within the viewport. It stores no merged pair contexts. Overlapping modification calls choose the highest probability, with the first mate winning equal-probability ties at the same coordinate.

DataFrame row selection, transformations, joins, and grouped aggregations use lazy Polars expressions, including batch concatenation, overlap filters, base events, viewport projections, and pair construction. Simple column statistics use direct typed reductions, including coverage sums, maximum row positions, and visibility checks. Queries call `.collect()` directly when a concrete DataFrame is needed. DataFrames are constructed directly only at ingestion boundaries; typed columns are read when consuming query results. Base filtering and sorting query CIGAR tables directly, using aligned SEQ characters and deletion, reference-skip, and insertion events. The query emits numeric priorities for A, T, C, G, N, other bases, deletions, insertions, and pair gaps, without a separate sort-key enum. Polars sorts these priorities and stable read or pair IDs; the stacker then assigns rows and packs the remaining visible items. Aligned bases take precedence over deletions and insertions at a shared cursor, and pair keys prefer the first visible mate, then the second mate, then a pair gap. There is no `AlignedRead` or `AlignedReadRef` representation; fixtures and loaded reads use noodles `RecordBuf` directly. Mouse descriptions format the original record without a geometry wrapper. No SQL context, Python binding, or disk format is introduced by this refactor.

Polars errors convert automatically into `TGVError::PolarsError`, preserving the underlying error as a source. Table construction and queries propagate them with `?`; domain validation errors retain their read IDs and specific diagnostics.

## Coverage

`Alignment.coverage` owns an independent `CoverageTable`, defined in `gv-core/src/alignment/coverage.rs`. Its public `data` DataFrame stores sparse rows sorted by one-based `pos`, with `A`, `T`, `C`, `G`, `N`, `total`, and `softclip` as `UInt64`, and `reference_base` as `UInt8`. The count columns match the scalar `u64` fields of `Coverage`; positions and reference bases belong only to the table. Soft clips contribute only to `softclip`, and missing positions return zero coverage. A temporary sorted accumulator builds the columns; no coverage map remains stored in `Alignment`.

Coverage is rebuilt from visible CIGAR runs at construction and after filtering. `CoverageTable::from_runs` constructs coverage from visible CIGAR projections. Its `query` method returns a temporary `Coverage` containing summed `u64` counts for the inclusive interval, without positions or reference bases. `Coverage` provides read-only description and alternate-depth helpers; it has no mutation or accumulation methods. Rendering queries one summary per bin, and mouse descriptions use the interval summary directly. `query_rows` provides sparse rows for per-position inspection and reference-base lookup. Both query methods express the inclusive interval predicate lazily, and `query` sums the selected count columns using direct typed column reductions. Construction uses a temporary sorted count accumulator, independent of `Coverage`.
