# Alignment tables in memory

The alignment schemas, table construction, and sparse annotation helpers live together in `alignment/tables.rs`. Each loaded alignment region has Polars tables for reads, all nine CIGAR operation kinds in one `cigar_runs` table, records without CIGAR operations, and sparse base annotations. The core columns follow the LAMF alignment map layout, except that SEQ payloads use UTF-8 strings for simpler access. `ContigHeader` remains the authority for merged contig names and references; there is no separate reference or header table in memory.

## Read identity and display bounds

The `read_id` column is the zero-based position in the region's original record order. `Alignment` owns exactly one decoded `RecordBuf` for each ID. Filtering, sorting, and pairing keep these IDs stable so the viewer can retrieve original CIGAR operations, tags, and read details without reconstructing a record from the tables.

The reads table adds nullable `UInt64` columns `stacking_start` and `stacking_end`. They describe one-based, inclusive display bounds, including projected soft clips. Both are null for records without an alignment position. Stacking, overlap queries, hit testing, sorting, and pair construction use these columns. There is no stored read geometry vector or separate spans table. Visibility and track positions are columns in the read and pair tables; loaded-region bounds remain application state beside the tables. Genomic positions use tgv’s one-based, inclusive convention throughout the tables, queries, annotations, and renderer. Read IDs, operation indexes, and offsets into SEQ remain zero-based indexes.

Repository readers convert local BAM, remote BAM, and CRAM records into noodles `RecordBuf`s in batches of 1,024 records. Tables are populated with a consuming builder, starting with `AlignmentTables::default().add_records(&batch, &reference, contig_index)?`. Each call builds columns for the new records and appends DataFrame chunks using `vstack_mut`, rather than rebuilding the existing rows. IDs continue from the existing reads table height, including IDs in CIGAR, unmapped, and annotation tables. Empty batches leave the tables unchanged. Batches for one region use the same header, reference, and contig index. Appending succeeds for the complete set of tables before the builder returns.

All table fields are public, so callers use `tables.reads`, `tables.cigar_runs`, and `tables.base_modifications` directly. `CigarSchema` declares the run columns and explicit BAM operation codes as `u8` constants. Ingestion maps noodles CIGAR kinds once; queries and rendering use these constants directly. The owning alignment and pair table follow the same field-access convention.

Noodles supplies SAM flags and the source records. Read-consuming CIGAR runs and the unmapped table store SEQ as Polars `String` (UTF-8), preserving the ASCII sequence from the original `RecordBuf`. Base offsets are therefore byte offsets, and there is no custom four-bit packing or decoding. Missing read names, mapping qualities, SEQ, and quality scores are null. This uses more memory than packed bases but simplifies slicing, comparisons, queries, and eventual Python access. Present quality payloads remain binary. Optional tags remain exclusively in the original `RecordBuf` objects and can be queried through `alignment.records[read_id].data()`. There is no duplicate tags table. Batch construction uses separate append functions for read fields, CIGAR runs, and unmapped payloads, each updating mutable vectors directly. DataFrames are constructed inline in the private `build_batch` free function, without wrapper structs or a second row-oriented copy.

The read table stores mutable display state in `show: Boolean` and `y: UInt64`. Filtering replaces visibility, and stacking or base sorting replaces row positions, without removing or reordering stable read-ID rows. The stacker uses a temporary vector to build the y column; no display vectors or y-index cache remain in `Alignment`. Hidden rows receive y zero. Depth uses direct column reductions to check visibility and compute the maximum zero-based y plus one, returning zero when no rows are visible. Hit testing uses lazy row selection.

## Sparse annotations

A CIGAR run is uniquely identified by `(read_id, op_index)` in the unified run table. The reference mismatch table stores that key, `run_offset: UInt32`, `ref_pos: UInt64`, and `base: UInt8`. It contains only mismatches discovered by comparing `M` bases with the loaded reference at construction time. Explicit `X` runs already identify mismatches, and `=` runs are trusted. Unavailable reference positions and other contigs are never compared.

The base modification table stores the run key, `run_offset: UInt32`, `display_pos: UInt64`, nullable `code: UInt8` and `chebi_id: UInt32`, `probability: UInt8`, and `source_order: UInt64`. Exactly one modification variant is populated, matching noodles' `Modification`. Coordinates are one-based and include projected soft clips. Inserted bases have no projected reference position, so their original annotations remain available in the original record sidecar. MM/ML parsing supports the legacy tags, preserves absent probabilities as null (the renderer retains its display default of 255), and preserves source order. Invalid MM data produces a diagnostic containing the read ID during loading.

A reference cache refresh constructs replacement mismatch tables directly from each alignment’s `M` runs and contig index before committing the sequence and annotations. Cached reads do not need to be reloaded. Annotation storage is separate because a run can have many optional base annotations, and their coordinates and probabilities should be independently queryable.

## Viewport drawing and paired reads

There are no `RenderingContext` objects, `AlignmentViewport` bundles, or viewport query methods. The caller passes the first visible alignment row explicitly as `top`; the renderer derives the visible row range from `top` and the area height, and maps stored rows to terminal rows without a track-index lookup. Rendering builds a lazy selection of visible read rows and joins it to runs whose stored display bounds overlap the viewport. One collection yields run geometry, SEQ, and the read's `y`, strand, and stacking bounds. Pair gaps are drawn independently of the run query, so a gap can cross the viewport while both mates remain outside it. Clipping happens while drawing: the renderer clamps the stored display bounds to the viewport and adds the skipped prefix to `run_offset`. Stored offsets preserve bases clipped before coordinate 1. Hard clips and padding consume no display interval, and insertions retain their reference cursor as a point anchor.

Sparse mismatch and modification queries join the selected reads directly, carry their displayed rows, and filter annotation positions independently. Keeping annotations separate avoids expanding each run for every optional base annotation. Order-preserving joins retain the stored read/CIGAR order and annotation source order without rendering sorts or distinct-ID queries. The renderer writes directly into the terminal buffer in successive layers: pair gaps, run bodies and soft clips, strand arrows, insertions, explicit `X` mismatches, sparse reference mismatches, and base modifications. Later writes win within each layer, including at compressed zoom levels. Glyph overlays preserve the background, and modifications change only the background. There are no scratch terminal cells or comparisons against previously drawn operations.

The paired view owns a Polars pair table with `pair_id`, `read_1_id`, nullable `read_2_id`, and nullable stacking bounds in the same one-based, inclusive convention. Both pair and singleton rows store `show: Boolean` and `y: UInt64`. Visibility and row placement have no parallel vectors or y-index cache. Polars groups primary, nonsupplementary paired reads by non-null `qname`. Each qname produces one group containing its minimum and maximum read IDs; groups with one record have a null second ID. Additional records in a group do not create more pairs. A final sort by the first read ID keeps pair IDs deterministic. Missing names, unpaired records, secondary records, and supplementary records remain in the separate `singles` DataFrame. An eligible read without a loaded mate stays in the pair table with a null second ID. Pairs and singles share one stacking space, and both participate in sorting, rendering, and mouse hit queries. The renderer selects both mates and singletons for the shared drawing pipeline, respecting each read's visibility. Gaps are drawn only between two visible, positioned, nonoverlapping mates, before the runs. Mate overlaps use the same later-write-wins rule as other cell collisions, without conflict markers or merged pair contexts. Modification backgrounds follow stored source order, without probability arbitration; absent probabilities retain the display default of 255.

DataFrame row selection, transformations, joins, and grouped aggregations use lazy Polars expressions, including batch concatenation, overlap filters, base filters, rendering joins, and pair construction. Simple column statistics use direct typed reductions, including coverage sums, maximum row positions, and visibility checks. Queries call `.collect()` directly when a concrete DataFrame is needed. DataFrames are constructed directly only at ingestion boundaries; typed columns are read when consuming query results. Base filtering and sorting query CIGAR tables directly, using aligned SEQ characters and deletion, reference-skip, and insertion events. The query emits numeric priorities for A, T, C, G, N, other bases, deletions, insertions, and pair gaps, without a separate sort-key enum. Polars sorts these priorities and stable read or pair IDs; the stacker then assigns rows and packs the remaining visible items. Aligned bases take precedence over deletions and insertions at a shared cursor, and pair keys prefer the first visible mate, then the second mate, then a pair gap. There is no `AlignedRead` or `AlignedReadRef` representation; fixtures and loaded reads use noodles `RecordBuf` directly. Mouse descriptions format the original record without a geometry wrapper. No SQL context, Python binding, or disk format is introduced by this refactor.

Polars errors convert automatically into `TGVError::PolarsError`, preserving the underlying error as a source. Table construction and queries propagate them with `?`; domain validation errors retain their read IDs and specific diagnostics.

## Coverage

`Alignment.coverage` owns an independent `CoverageTable`, defined in `gv-core/src/alignment/coverage.rs`. Its public `data` DataFrame stores sparse rows sorted by one-based `pos`, with `A`, `T`, `C`, `G`, `N`, `total`, and `softclip` as `UInt64`, and `reference_base` as `UInt8`. Soft clips contribute only to `softclip`, and positions without coverage have no stored row. A temporary sorted accumulator builds the columns; no coverage map remains stored in `Alignment`.

Coverage is rebuilt from visible CIGAR runs at construction and after filtering. `CoverageTable::from_runs` accepts a lazy run query, filters base-bearing runs with display bounds, and collects once. Construction joins visible read IDs directly to stored runs, without read-ID vectors, viewport projection, or annotation queries. Its only query method, `query`, selects sparse rows in a one-based, inclusive interval using a lazy predicate and returns a DataFrame. There is no temporary `Coverage` struct. Rendering queries the viewport once, bins the sorted rows locally, and computes alternate depth from each row’s counts and reference base at single-base zoom. Mouse handling sums the selected count columns using direct typed column reductions and formats the interval totals. Server inspection consumes the per-position rows and supplies zeros for absent positions. Construction uses a temporary sorted count accumulator.
